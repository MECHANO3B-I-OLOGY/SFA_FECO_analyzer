\section{Getting started}

	The SFA FECO Analyzer is a Python-based tool for analyzing motion in grayscale TIFF images generated by the Surface Fores Apparatus, providing interactive features such as image cropping, wave centerline analysis, and post-analysis data cleaning. The tool allows users to crop the region of interest from the input image, analyze the wave motion across frames, interactively delete unwanted or broken data points from the results, and finally generate force-distance profiles from the data.
	The goal of the software is to be easy to use while still allowing for modularity and ability to analyze data in other software. This manual is up to data as of version \textit{2.3.0}.

	\subsection{Methods of Installation}

		There are three primary methods of installing the software, listed below in order of recommendation:

		\begin{enumerate}
			\item Download executable from Github
			\item Pull source code from Github
			\item Compile executable from source code
		\end{enumerate}

		\subsubsection{Downloading executable}

			Provided on the \href{https://github.com/MECHANO3B-I-OLOGY/SFA_FECO_analyzer}{Github page} for this project are multiple compressed files for different operating systems. Currently, executables have been provided for Windows (win86\_64.zip), Mac (mac.zip), and Linux (linux86.tar.gz). If you wish to run the software from a different operating system or architecture, please continue to the section ``\textit{1.1.2 Pulling Source Code}''.
			After downloading and extracting the archive file, there will be a main.exe file and a folder called \textbf{\_internal}. These two files must stay next to each other, and from here, the executable may be executed as normal, without the need to download python or set up any other environment. 
			This option is preferred for users who want want the program ready without any setup, those who want more stability, and those who are less familiar with version handling. 

		\subsubsection{Pulling source code}

			Should you wish to download the source code and run the program directly, you can start by running the following command:

			\begin{lstlisting}[style=cmd]
$ git clone https://github.com/MECHANO3B-I-OLOGY/SFA_FECO_analyzer.git
			\end{lstlisting}

			Cloning the repository to your current directory. From here, the script can be ran using the following:

			\begin{lstlisting}[style=cmd]
$ python run.py
			\end{lstlisting}

			Do note that the program is made for python versions 3.12 and 3.13, and any other versions will likely cause a versioning error when attempting to download the prerequisite packages.
			On the first execution of the script, it will take a few minutes to download the packages and save them to a virtual environment at \textbf{./venv/}. 
			Future executions will use the version of python within the venv, so the version requirement will not necessarily require any specific python3 version.
			This option is preferable for those who intend to make edits the script, contribute to the github, or who want an easier method of upgrade on new releases of the script.


			\paragraph{Upgrading} When pulling the source code, the script can be updated by running:

			\begin{lstlisting}[style=cmd]
$ git pull
			\end{lstlisting}

			Do check if the \textbf{requirements.txt} file has been updated; if so, it will be necessary to manually delete the \textbf{./venv/} directory and redownload them via the \textbf{run} script.

		\subsubsection{Compiling executable}

			If you wish to compile your own version of the software, the file to compile the program is included. First, start by completing the steps in ``\textit{1.1.2 Pulling Source Code}''.
			After verifying the virtual environment has installed correctly. Run the following commands to download \textit{Pyinstaller} to your venv, which is the compiler used for this project, and compile the executable.


			\paragraph{Windows} \phantom{text}

			\begin{lstlisting}[style=cmd]
> .\venv\Scipts\activate
(venv) > pip install pyinstaller
(venv) > pyinstaller.exe main.spec --clean
			\end{lstlisting}

			\paragraph{Unix-like} Mac/Linux/BSD/etc

			\begin{lstlisting}[style=cmd]
$ source ./venv/bin/activate
(venv) $ pip install pyinstaller
(venv) $ pyinstaller main.spec --clean
			\end{lstlisting}

			This process usually takes around five minutes. This command will create a directory \textbf{./dist/main/}, where both \textbf{.dist/main/main} (or \textbf{.\textbackslash dist\textbackslash main\textbackslash main.exe} on Windows) and \textbf{./dist/main/\_internal} will be created. 
			One final manual step will be to move the directories \textbf{./bfconverter/} and \textbf{./images/} into the \textbf{./dist/main/\_internal} directory. Once these steps are completed, running the generated executable will open the software.

	\subsection{General Conventions}

		For the usage of this software, two primary assumptions will be placed on video files used for the software. First, it will be assumed that the convention was taken that lower wavelengths of light are on the left, and higher wavelengths are on the right. 
		If this convention is not followed, multiple features such as the dispersion calculation and main line tracking will not function as expected. The second convention is that the file is an 8-bit file. By default, CXD files will follow this convention, and most tiff files will as well.
		However, if you attempt to load a file and it comes back as static, the file is more than likely 16-bit, and will need to be ran through a program such as \textit{Fiji} to convert it to 8-bit before continuing.

		Additionally, it should always be assumed that when a portion of the program opens a new window, that window will not respond to changes made in the main window. For instance, if the user forgets to select which mercury lines will be visible in the process of dispersion calculation, they should first close the dispersion calculation window before selecting the relevant mercury lines.
		Changing information on the main window while a secondary window is open may lead to unexpected behavior.
